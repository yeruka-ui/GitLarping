What is SCM?

Software Configuration Management is the discipline of identifying, controlling and tracking every change to a software system, so a team always knows what was built, from what, and why.

  • Version Control

    Git records every change as a commit with an author, a timestamp and a reason. Branches let work happen in parallel; pull requests bring it back together under review.

    Configuration identification and change control: the history is the source of truth.

  • CI/CD

    Continuous Integration builds and checks every push automatically. Continuous Delivery packages what passed and deploys it, so releases are small, frequent and repeatable.

    If a check fails, the release stops. Nobody has to remember to run it.

  • DevOps

    The culture that joins development and operations: shared ownership, automation over manual steps, and fast feedback from production back to the people writing the code.

    Tools make it possible; habits make it work.

From commit to live

Four stages, defined in .github/workflows/deploy.yml. If any stage fails, nothing after it runs.

  1. 01Push

    A commit lands on main (or someone clicks "Run workflow"). GitHub Actions starts a fresh runner.

  2. 02Lint

    npm ci installs the locked toolchain, then npm run lint checks the JavaScript. Any error stops the pipeline here.

  3. 03Package

    Only the files the site needs (index.html, css/, js/) are copied into _site and uploaded as an artifact.

  4. 04Deploy

    The artifact is published to GitHub Pages and the live URL is shown on the workflow run.
